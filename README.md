# KAZEROS — запуск на Bothost

Сборка 1.1.1 · Интерфейс KAZEROS v1.1 · 8 октября 2026

## Что изменено для хостинга

Главный файл: `main.py`. Установка Python на ваш компьютер не нужна.
Настройки читаются из переменных окружения Bothost; локальный config.json не обязателен.
Токен читается из DISCORD_TOKEN, DISCORD_BOT_TOKEN или BOT_TOKEN (в таком порядке).
Данные участников и два последних снимка персонажа хранятся в `/app/data/coach.sqlite3`.
Исходная база в архив не включена. Правила и интерфейс разбора сохранены из v1.1.
Новая сборка не добавляет босса, таймеры, платный ИИ или доступ к игровому аккаунту.

## 1. Подготовьте Discord

Если KAZEROS уже создан, используйте существующее приложение, не создавайте второе.
Откройте https://discord.com/developers/applications → KAZEROS → Bot.
Bot Token берётся через Reset Token. При сбросе старый токен перестаёт работать.
Вводите токен только в поле Bot Token в кабинете Bothost. Не отправляйте его в чат.

Если бот ещё не добавлен на ваш Discord-сервер:
Installation → Guild Install → scopes `bot` и `applications.commands`.
Разрешения: View Channels, Send Messages, Embed Links. Administrator не нужен.
Скопируйте Install Link, откройте его и выберите «Добавить на сервер».
Привилегированные intents не нужны. Interactions Endpoint URL оставьте пустым:
эта программа принимает команды через Discord Gateway, не через вебхук.

Получите ID сервера Discord:
Discord → настройки пользователя → Расширенные → Режим разработчика.
Правый клик по значку вашего сервера → Копировать ID сервера.
Это длинное число, не Application ID бота и не игровой ID 1312.

## 2. Выберите способ загрузки

У присланной страницы «Создать бота» есть обязательное поле Git URL:
это режим загрузки из Git, ZIP туда не вставляется.

### Вариант А. ZIP — для Базового или Pro

По официальной документации Bothost загрузка архивов доступна на Базовом и Pro,
пока на одной тестовой ноде. Это ограничение сервиса, не нашей программы.
Тариф и доступность в вашем аккаунте нужно проверить; на хостинг из чата ничего не загружено.

1. Bothost → Профиль → Интерфейс.
2. Включите «Загрузка бота из архива» и сохраните настройки.
3. Откройте «Мои боты» → «Загрузить из архива» (не обычное «Добавить бота»).
4. Выберите KAZEROS_Bothost_v1.1.1.zip. Распаковывать ZIP для этой загрузки не надо.
5. Нажмите «Далее».
6. Название: KAZEROS. Токен: Bot Token вашего Discord-приложения.
7. Язык/шаблон: Python, не aiogram. Главный файл: main.py.
8. Если доступен выбор версии Python, выберите 3.13; подсказка уже есть в bothost.json.
9. Нажмите «Задеплоить».
10. Откройте настройки созданного бота → Переменные окружения и заполните раздел 3.

В опубликованном примере ZIP-мастера нет поля переменных окружения. Поэтому
при первом запуске до шага 10 бот может остановиться с сообщением [НАСТРОЙКА]
о DISCORD_GUILD_ID. Это не требует повторной загрузки архива: добавьте переменную,
сохраните настройки и перезапустите бота, чтобы он получил новое окружение.

Если ваш мастер показывает переменные до деплоя, заполните их сразу.
Если архивная нода недоступна, либо не принимает Discord-токен/не имеет связи с
Discord, используйте вариант Б с локацией Нидерланды. Не подменяйте Discord-токен Telegram-токеном.

### Вариант Б. Git — через присланную форму

1. Создайте репозиторий `kazeros-bot` на GitHub.
2. Самый простой путь — Public: код станет общедоступным. Используйте его только
   если согласны публиковать исходники. В этой сборке нет ваших токенов или данных.
   Private сохраняет код закрытым, но потребует подключения приватного репозитория
   в Bothost. Не вставляйте пароли или GitHub-токены в Git URL.
3. Распакуйте ZIP. На GitHub нажмите Add file → Upload files (или ссылку uploading
   an existing file для пустого репозитория).
4. Загрузите файлы и каталоги ИЗНУТРИ архива. В корне репозитория должны быть
   main.py, bot.py, requirements.txt, bothost.json и папка kazeros.
   Не загружайте ZIP как один файл. Не вкладывайте весь проект в лишнюю папку.
5. Сохраните изменения в main через Commit changes / Propose changes.
6. Git URL для Bothost: https://github.com/ВАШ_ЛОГИН/kazeros-bot.git
7. Заполните форму Bothost:
   - Название бота: KAZEROS;
   - Платформа: Discord;
   - Язык разработки: Python / discord.py;
   - Версия Python: 3.13;
   - Bot Token: токен Discord;
   - Локация: Нидерланды (Амстердам);
   - Переменные окружения: раздел 3;
   - Git URL: ссылка выше со своим логином и окончанием .git;
   - Ветка: main (либо точное имя вашей ветки);
   - Дополнительные настройки → Главный файл: main.py;
   - Использовать домен: выключено;
   - Использовать собственный Dockerfile: выключено.
8. Нажмите «Создать бота» и следите за логами.

## 3. Переменные окружения

В каждой строке есть отдельное поле «Ключ» и отдельное «Значение».
Не добавляйте знак = к ключу и не ставьте кавычки вокруг значений.

| Ключ | Значение |
|---|---|
| DISCORD_GUILD_ID | Ваш длинный числовой ID сервера Discord |
| GAME_REGION | eu |
| GAME_SERVER_ID | 1312 |
| GAME_SERVER_NAME | Luteros |
| KAZEROS_DATA_DIR | /app/data |

Обязательно ввести свой DISCORD_GUILD_ID. Остальные значения повторяют настройки
этой сборки. EU / Luteros сохранён из предыдущего проекта; если нужен другой игровой
сервер, задайте его параметры, либо GAME_SERVER_ID=0 для поиска по всему региону.
В Bot Token укажите только токен Discord. Вручную дублировать его тремя переменными
не нужно. Если в логах сказано, что токен не передан, добавьте DISCORD_TOKEN с тем же
значением в секретные настройки и перезапустите бота. При смене токена обновите и
явно добавленную переменную DISCORD_TOKEN, иначе она перекроет новое значение Bot Token.

## 4. Первый запуск

Дождитесь в логах строки «Бот готов: …».
Затем в Discord в канале #прокачка выполните /панель от участника с правом
«Управлять сервером». Панель сама не публикуется при загрузке на хостинг.

Нажмите «Мой персонаж» → введите ник → выберите персонажа из результатов →
выберите цель, роль, бюджет → «Сохранить и разобрать».
Проверьте, что результаты личные и нажатие «Обновить» не выдаёт ошибку.
После перезапуска Bothost проверьте ещё раз /разбор: привязка должна остаться.

Не запускайте одновременно домашнюю и серверную копии с одним токеном.
После успешного серверного запуска держать домашний компьютер включённым не нужно.

## 5. Ошибки

- [НАСТРОЙКА] DISCORD_GUILD_ID — добавьте именно ID Discord-сервера в окружение.
- Токен не принят / 401 — обновите Bot Token; не путайте с Public Key или Client Secret.
- Бот онлайн, /панель нет — проверьте правильный DISCORD_GUILD_ID, приглашение
  с applications.commands и доступ бота к каналу; переоткройте Discord.
- Forbidden / Missing Access — бот должен быть приглашён на тот сервер,
  чей ID указан в настройках. Для канала нужны View Channels, Send Messages, Embed Links.
- ModuleNotFoundError — requirements.txt должен лежать в корне. Выполните пересборку.
- Не найден main.py — проверьте точку входа и структуру архива/репозитория.
- Оружейная не отвечает — это отдельное соединение; подключение к Discord ещё
  не подтверждает доступность игрового источника. Нужна проверка по логам.
- Данные потерялись — проверьте KAZEROS_DATA_DIR=/app/data и постоянное хранилище.

Не публикуйте содержимое токена или .env вместе с логами.

## 6. Обновления и резервная копия

Для бота из ZIP используйте загрузку нового архива в его карточке.
Для бота из Git — обновление из Git; в первый раз используйте тот же метод при обновлении.
По документации Bothost, /app/data сохраняется между обновлениями. Это не замена бэкапу.
Перед ручной копией базы остановите бота и скачайте папку data целиком, затем запустите.
Если раньше бот работал на ПК и уже есть нужные привязки: остановите обе копии,
перенесите содержимое runtime с coach.sqlite3 и имеющимися sqlite3-wal/sqlite3-shm
в /app/data через файловый менеджер Bothost, затем запускайте только серверную копию.
Не загружайте базу в публичный Git.

## Проверка этой сборки

Проверены синтаксис Python и 54 офлайн-теста: 19 конфигурации/хранилища, 14 правил
рекомендаций, 21 адаптера оружейной на тестовых ответах. Эти тесты не запрашивают
реальных персонажей и не авторизуются в Discord. Проверен понятный выход при
отсутствующем DISCORD_GUILD_ID.

В этой среде не установлена discord.py, а установка из PyPI заблокирована сетевой
ошибкой DNS. Поэтому Discord UI-тесты test_app.py, полный старт бота, Docker-сборка
и загрузка на ваш Bothost здесь НЕ выполнялись. aiohttp-тесты шли с установленной
3.13.3; requirements.txt для сервера сохраняет зависимости проекта: discord.py 2.7.1,
aiohttp 3.14.4. Финальная интеграционная проверка — по логам Bothost и вашему профилю.
